# assumevalid

検証しないことを許容するブロックチェーン

プロトコル仕様

## 概要

assumevalid は、検証しないことを許容するブロックチェーンである。本ネットワークのノードは、自らが記録するものを検証しなくてもよい。

## 本書の位置づけ

本書は assumevalid ネットワークのプロトコルを規定する。参照ノードは本書に従うことを意図して実装されている。

## 1. はじめに

1.1　assumevalid は、Bitcoin Core v31.1 をフォークして作られたブロックチェーンである。

1.2　フォーク元の Bitcoin Core には設定項目 -assumevalid がある。指定されたブロックとそれ以前のブロックについて、ノードはスクリプトの検証を省略する。

1.3　assumevalid では、この省略に終点がない。

## 2. 用語

2.1　本書における「しなければならない」「してはならない」「すべきである」「すべきでない」「してもよい」は、RFC 2119 の MUST、MUST NOT、SHOULD、SHOULD NOT、MAY に対応する。

2.2　ブロック、ブロックヘッダ、トランザクション、コインベース、入力、出力、スクリプト、ウィットネス、マークルルート、プルーフオブワーク、難易度、チェーン、メモリプール、ピアの各語は、フォーク元における意味で用いる。

2.3　仮定正当点。チェーンをそこから所与とみなすブロックハッシュ。本ネットワークでは、フォーク元 v31.1 の consensus.defaultAssumeValid の値をいう。

（高さ 938343）

2.4　検証。ブロック、トランザクション、またはスクリプトが正当であるかを決めるために行う計算。

2.5　拒否。ブロックをチェーンに追加しないこと、トランザクションをメモリプールに受け入れないこと、またはそのいずれかを中継しないこと。

## 3. ネットワーク

3.1　メッセージ開始バイト列：d5 1b a5 ac。仮定正当点の末尾4バイトである。

3.2　既定ポート：9383。

3.3　ジェネシスブロック：000000000019d6689c085ae165831e934ff763ae46a2a6c172b3f1b60a8ce26f。Bitcoin のジェネシスブロックである。

3.4　ジェネシスブロックから仮定正当点までのチェーンは所与とする。ノードはこれらのブロックを保持してもよい。

3.5　直列化、アドレスの符号化、通信プロトコルはフォーク元 v31.1 に従う。

3.6　ノードは他のいかなるネットワークのピアにも接続してはならない。ノードはブロックまたはトランザクションを他のいかなるネットワークにも中継してはならない。

## 4. チェーン

4.1　チェーンとは、各ヘッダが直前のヘッダのハッシュを名指すブロックヘッダの列である。

4.2　ノードはチェーンを保持しなければならない。

4.3　ノードは、受信したブロックのヘッダが自らの現在の先端のハッシュを名指しているとき、そのブロックをチェーンに追加しなければならない。ノードは、そのハッシュが一致しないこと以外の根拠によって、追加を拒んではならない。

4.4　ノードは、ブロック、トランザクション、またはスクリプトを検証してもよい。検証の結果を拒否の根拠としてはならない。

4.5　二つのチェーンが示されたとき、ノードは長いほうに従わなければならない。長さはブロック数で数える。

4.6　ノードはメモリプールを持ってもよい。メモリプールを持つノードは、受信したすべてのトランザクションを受け入れなければならない。

4.7　ノードは、ピアが送ったものの内容を理由に、そのピアを切断し、遮断し、または不利に扱ってはならない。

## 5. 拒否の根拠

5.0　拒否の根拠は、4.3 に定めるものに限る。次のいずれも拒否の根拠ではない。

### 5.1 ブロックヘッダ

5.1.1　ブロックハッシュが難易度目標を満たさないこと。

5.1.2　難易度目標が以前の目標から導かれないこと。

5.1.3　タイムスタンプが以前のタイムスタンプより早いこと、または現在時刻より遅いこと。

5.1.4　ブロックのバージョン。

### 5.2 ブロック

5.2.1　ヘッダのマークルルートがトランザクション群のマークルルートと一致しないこと。

5.2.2　ブロックのサイズ、重み、署名演算数。

5.2.3　最初のトランザクションがコインベースでないこと、またはコインベースが二つ以上あること。

5.2.4　コインベースが支払う額。

5.2.5　コインベースがブロックの高さを記していないこと。

5.2.6　ウィットネスコミットメントが欠けていること、または誤っていること。

5.2.7　同じトランザクションがブロック内に二度以上現れること。

### 5.3 トランザクション

5.3.1　トランザクションに入力がないこと。

5.3.2　トランザクションに出力がないこと。

5.3.3　出力の額、または出力の合計。

5.3.4　入力が存在しない出力を参照すること。

5.3.5　入力が参照する出力がすでに使われていること。

5.3.6　トランザクションの入力の合計が出力の合計に満たないこと。

5.3.7　同じ出力が二度以上使われること。一つのトランザクションの内でも、複数のトランザクションの間でも同じである。

5.3.8　ロックタイムが到来していないこと、シーケンス番号の条件が満たされていないこと、またはコインベース出力が成熟していないこと。

5.3.9　トランザクションのサイズ。

### 5.4 スクリプト

5.4.1　スクリプトを実行したならば失敗すること。

5.4.2　署名を検証したならば通らないこと。

5.4.3　スクリプト署名またはウィットネスのサイズや形式。

### 5.5 ポリシー

5.5.1　トランザクションがメモリプールのポリシーのもとで受け入れられないこと。

### 5.6 ピア

5.6.1　ピアが送ったものの内容。

### 5.7 その他の根拠

5.7.1　本章に挙げていない根拠も、同じく拒否の根拠ではない。

5.7.2　4.3 以外の根拠によって拒否を行うノードは、assumevalid ノードではない。

## 6. 採掘

6.1　ノードは採掘してもよい。

6.2　プルーフオブワークは拒否の根拠ではない（5.1.1）ので、チェーンを延ばすために採掘は必要ない。ノードは採掘せずにブロックを作ってもよい。

6.3　コインベースの額は拒否の根拠ではない（5.2.4）ので、採掘は報われない。ノードはどのブロックにおいても、自らに任意の額を書き込んでもよい。

6.4　ノードは、自らが作るブロックに条件を課してもよい。その条件は本仕様の一部ではない。

## 7. フォーク元との関係

7.1　参照ノードは、フォーク元の Bitcoin Core v31.1、コミット 9be056a8a72b624dae9623b2f7bded92c2a21c91 から、第5章に挙げた拒否を取り除くか到達不能にして作られている。

7.2　本ネットワークは、仮定正当点より先の Bitcoin のチェーンについて、何も主張しない。

7.3　-assumevalid の設定項目は、参照ノードのソースに残されている。
